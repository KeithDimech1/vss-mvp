## 🗓️ WEEK 2: Discovery Workshops

### Workshop Facilitation Guide

**Standard Workshop Structure:**
```
0:00-0:05: Welcome & Icebreaker
0:05-0:15: Context Setting (this system's purpose)
0:15-0:40: Diagnostic Questions (collaborative)
0:40-0:55: Synthesis & Key Findings
0:55-1:00: Action Items & Next Steps

Total: 1 hour (extend to 1.5-2 hours if needed)
```

**Facilitation Tips:**
- Start on time, end on time
- Use timer for sections
- Ensure everyone speaks
- Capture everything in Miro
- Synthesize to Notion during or after
- Share summary within 24 hours

### Monday: System 1 Operations Workshop

**Time:** 2 hours
**Participants:** All directors + Juan, key ops people
**Miro Board:** VSM Current State Canvas
**Notion Page:** Systems Database → System 1

#### Prep (30 min before)
```
└── Set up Miro board with structure
└── Open Notion page
└── Test screen share
└── Prepare questions list
```

#### Workshop Agenda (2 hours)

**Part 1: Identify System 1 Units (30 min)**
```
Questions to explore:
1. What are our operational units?
   └── Answer: LithoSurfer, LithoBuild, LithoData

2. For each unit, can it:
   ├── Operate independently? (Yes/No + explanation)
   ├── Be sold separately? (Yes/No + explanation)
   ├── Have its own customers? (Who?)
   ├── Produce clear outputs? (What?)
   └── Have its own management? (Who?)

3. Are there other units we're missing?
   └── LithoAI? (Not yet operational)
   └── Other sub-systems?

Capture in Miro with sticky notes, discuss, consensus
```

**Part 2: Resources & Capabilities (30 min)**
```
For each unit (Surfer, Build, Data):

1. Who works primarily on this unit?
   └── List names, roles, % of time

2. What are this unit's key capabilities?
   └── Technical, domain knowledge, relationships

3. What resources does it need?
   └── People, tools, data, budget

4. Current state assessment:
   ├── What's working well? (Green stickies)
   ├── What are challenges? (Yellow stickies)
   └── What's broken? (Red stickies)

Create visual map on Miro for each unit
```

**Part 3: Boundaries & Interfaces (30 min)**
```
Questions:
1. Where do units overlap?
   └── Nora works on all three - is this a problem?
   └── Shared codebase - how to manage?

2. Where are boundaries unclear?
   └── Is X task Surfer or Data?
   └── Customer requests - which unit owns?

3. How do units interact?
   └── Data flows: Build → Data → Surfer?
   └── Dependencies?

4. Should boundaries be different?
   └── Redefine any units?
   └── Split or merge any?

Draw boundary lines and interface points on Miro
```

**Part 4: Synthesis & Actions (30 min)**
```
1. Summarize findings:
   ├── Confirmed 3 units: Surfer, Build, Data
   ├── Key strengths identified
   ├── Key gaps identified
   └── Boundary clarifications needed

2. Quick decisions:
   ├── Are these the right units? (Vote)
   ├── Do we need to reorganize? (Discuss)
   └── What's most urgent to address? (Top 3)

3. Action items:
   ├── Who: Captures outputs to Notion
   ├── Who: Communicates to broader team
   ├── Who: Begins addressing urgent items
   └── What: Next steps for unclear items
```

#### Post-Workshop (1 hour)
```
Keith's tasks:
├── Clean up Miro board
├── Transfer findings to Notion Systems Database
├── Create summary document
├── Share with participants (24 hours)
└── Update Week 2 progress
```
